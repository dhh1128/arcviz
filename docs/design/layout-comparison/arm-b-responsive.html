Arm B — compression, rebuilt responsively

The picture below is one credential and the other credentials it points to — eleven of them, plus two that are referenced and not in hand. Every box is one credential. Only one box is ever opened at a time; the rest compress to a fixed small form so that the whole chain stays on one screen, which is the mechanism this arm is testing.

The reason any of it is drawn this way: a presented credential is full of different kinds of missing — absent, undisclosed, blinded, not in hand, unverified, stale — and the one thing a renderer must never do is let any of them look like each other, or like nothing being wrong. So the marks on the boxes are the point, not decoration. What each mark means is in the key below the picture.

Try two things. Click any box — it expands where it sits and everything else stays put. And drag the ribbed handle on the right edge of the picture, or use the width buttons below: the boxes repack, the connectors re-route, and the little direction arrows inside the boxes change to match the geometry they now describe. Nothing here is a coordinate; it is all a rule evaluated against the width the component is given.

Resizing the browser window will not do it, and that is not a bug in the window. The component caps its own width at 480 px and turns anything beyond that into margin — otherwise at desktop widths the whole graph flattens into a single row, which is the failure RESPONSIVE.md §10 is about. So above 480 px the picture is deliberately width-indifferent, and the handle is how you see it move. Press full width to watch it flatten.

Same thirteen objects and same host stubs as arm-b-compression.html, which was authored at a fixed 360 px. Measurements and findings: RESPONSIVE.md.

READER'S KEY — exhibit apparatus, not part of the component

The component itself carries no legend, on purpose: the design uses point-of-use captions instead, so that nothing has to be looked up elsewhere while reading a credential. This key exists because this page is a working exhibit and its reader has not memorised the vocabulary. Do not read it as a reversal of that decision — and if the picture turns out to need it, that is a finding about the design, not about the page.

A plain box
One credential in the presentation. The small number on it (03, 07…) is an opaque label supplied by the host — it is not anything from the credential, deliberately, so that nothing inside the render leaks which fixture it is.
The rounded pill
The credential's SAID — its self-certifying identifier — truncated. ×3 beside one means the same value occurs three times in this presentation.
Double border, hatched fill, NOT IN HAND
A hole: something this presentation refers to that was not supplied. The chain is severed here and the render says so rather than drawing a gap.
Top edge broken by the word stale
The host's freshness policy for that credential is exceeded. Expanded, the break carries the policy and the age; at the small form there is only room for the word.
No frame, four corner ticks
Possibly a metadata ACDC — a sketch of a credential that the issuer has committed to nothing of as presented. The frame withdraws to its corners because the evidence to resolve it either way was not supplied.
Porous (broken) bottom edge
A unit whose contents are committed but not disclosed, and are guessable — the schema reserves no blinding entropy, so the commitment protects nothing. It is drawn as leaky rather than locked on purpose: rendering this as "private" would assert a protection that does not exist.
Hatched strip along the top and down the left
The frontier: structure that is committed to exist but whose shape cannot be known. It is drawn at a fixed size and position always, so that its geometry can never respond to — and so leak — what it is hiding.
Solid arrowhead
A drawn reference to something that is in the layout. Open arrowhead: a reference whose destination is outside the layout's domain — it runs into the frontier.
A small tag like auth →
The edge's own label, taken verbatim from the credential's e section. It is issuer-chosen text, so it sits inside the box rather than on the connector — otherwise an issuer could label an edge and have the component appear to be saying it. The arrow is computed from where the connector actually got drawn.
⋯2 edges
That box has two edges and no room for either label. The shed is marked rather than silent, because a box showing one of two labels would imply it has one edge.

COMMENTARY — OUTSIDE THE RENDER

Host stubs, identical to the stress board and to all three arms: freshness policies P30D (items 01, 02), PT72H (03), PT12H (04, 08), none elsewhere; as-of 2026-06-14T00:00Z; render moment 2026-09-14T12:00Z; a SAID-verified schema document for item 11 only; no verification vectors, cause attestations, watchers, or presentation evidence. The load manifest is in ../stress-board/README.md, outside every render, per the host contract.

Determinism, restated for a responsive layout. The layout is a pure function of (presentation bytes, host stubs, focus SAID, available width). The width is a new argument and it is a declared input, like the host clock: two runs at the same width produce byte-identical output, and the conformance corpus has to pin a width per expected rendering rather than pin one width for all of them. Ordering is fixed by the presentation — objects appear in (band, SAID) order and wrapping never reorders them — so the mental-map property that orthogonal ordering preserves is preserved across both focus changes and width changes.

What is drawn versus what is packed. Only drawn edges connect anything. Row membership is a consequence of the width and carries no topology, which is why the same two objects can be adjacent at one width and in different rows at another; the caption inside the render says so at the point of use.

# Three-arm layout comparison — results

The artifact that decides how the composite lays out a credential DAG under density. Three mechanisms, built on the identical load — the stress board's eleven items, two drawn holes, one frontier, same host stubs, same 360 px viewport, same composite vocabulary ([synthesis.md §2](../charrette/synthesis.md)) — so every difference between the files below is the mechanism and nothing else. This README states measurements as measurements and answers the seven commissioned questions per arm. The load manifest (which corpus fixture is which `ITEM NN`) lives in [../stress-board/README.md](../stress-board/README.md) and deliberately not in any render.

## Files

- [arm-a-layering.html](arm-a-layering.html) — layering: occluded cards keep a visible top-edge sliver; all edges attach to visible geometry. Frames: rest (all slivers), focus (ITEM 08 whole in its pile), and the sliver gauge.
- [arm-b-compression.html](arm-b-compression.html) — compression: every non-focused object reflows to the 76×44 floor. Frames: rest (all floor, one viewport) and the stress board's measured 716 px focus frame, reproduced for like-for-like.
- [arm-c-doi.html](arm-c-doi.html) — degree-of-interest as importance-weighted space allocation: `tier(x) = max(state_floor(x), focus_tier − hops(x, focus))` over three discrete tiers, with the prominence budget as the a-priori-importance term. Frames: no-focus (API-only, which is also the print form) and focus on ITEM 05, the card chosen precisely because it carries no budgeted state — the API-term test.

**Greyscale:** as with the stress board, there are no separate greyscale files because there is no colour anywhere to remove — all three arms are authored hue-free (grep any file for non-grey colour values and find none), so each file is its own greyscale exhibit. The deliverable asked for a variant per arm; this is that deliverable satisfied by construction rather than by duplication, and it is stated here so the deviation is owned, not hidden.

## The seven questions, answered per arm

### 1. Sliver capacity (arm A's measured question)

A sliver at the 18 px floor carries: identity (6.5 px tag + 8 px pill + ×N mark), exactly one perimeter-class state (the stale frame-break at +7 px of height; the hole's double border; the two top corner ticks that are all a top strip can show of item 10's withdrawn frame), an e-slot glyph relocated inline, and — the sliver's one genuine advantage over the floor chip — 288 px of run-room, so the stale policy sentence survives verbatim at seven-point where the 76 px chip sheds it to the bare word, and item 09's cardinality bound survives in an abbreviated six-point form (the full sentence measured 352 px of run and did not fit even here — measured in headless Chrome, not estimated). Shed first: everything below line one (ledger, manifest, a-content, T detail), by construction and instantly; then the port strip's place-grammar — the seal survives only as an inline glyph, no longer at the place edges depart, so "same place, opposite structure" is lost; then the area-class deformations — item 11's transparent region has no area to spend and is words-only, which is one tier worse than the floor chip's degradation. The floor is 18 px because the pill's 8 px legibility minimum (stress board gauge A) is unchanged by reshaping; below ~16 px the sliver carries nothing at all.

### 2. Does the API term work (arm C)

Yes, for exactly the states it is defined over, and the test is drawn rather than argued: frame C2 puts focus on ITEM 05, which carries no budgeted state, one to five hops from every card that does. All five stale cards keep frame-break plus policy value (three policies remain three visibly different facts), item 10 keeps four corners and its possibly-line, item 11 keeps a drawn transparent a-region. The same focus position in arm B reduces all of that to six-point words. Two honest boundaries: the mid form's H6/H2 signatures are legible in the mock but their *comprehension* is exactly the P9 armchair limit — the small-n probe still owns that question; and the API term is card-scoped, so item 09's graph-level blinded-edge composition gets nothing from it — its bracket dies at the floor in C exactly as in B.

### 3. Unknowable distance

No arm crashes past it, because all three restrict the layout domain the same way; the difference is that only arm C has a formula the question could have broken. Arm A: pile position is rank; a blinded destination has no rank and never joins a pile; the frontier is never stacked. Arm B: distance is never computed; the frontier is fixed-size and fixed-position at every focus. Arm C, where `D` actually appears: a blinded edge's destination is outside the domain of `D` — DOI is never evaluated for it; the frontier is excluded from allocation by construction and rendered identically at every focus (independently forced by the fixed-size anti-leak rule — geometry that responded to focus would respond to what hides); cross-component `D` is undefined and the `max` form then has only its state-floor argument, which is a defined behaviour, not a fallback. A hole has a position via its disclosed in-edge, so `D` to a hole is defined; no path is counted through a hole, since its out-edges are unknown. The prior-art audit ([focus-context.md](../../research/prior-art/focus-context.md) §"The unknowable-distance question") found no literature defining any of this; the `max`-form domain restriction is this comparison's own construction and should be reviewed as such.

### 4. Co-presence and trace

At this load (13 drawn objects) every arm keeps everything co-present: rest registers fit in roughly one viewport (322 / 430 / 578 px) and focused registers in 1.1–1.6 viewports, so the stress board's fatal finding — budgeted markers off-viewport with no surviving trace at 6,884 px — does not recur in any arm. But the arms scale at different slopes, and the slopes say where each one re-enters the wound: at ≈ 15.5 px of column per added object, arm B holds a one-viewport rest register to roughly 30+ objects; arm A at 18–25 px reaches it around 25; arm C's budgeted carriers cost ≈ 41 px each, so a render where most cards carry budgeted states hits the viewport soonest — the honest statement is that C buys legibility per state by spending exactly the resource (column) whose exhaustion caused the original wound. None of the arms designs the edge-of-viewport residue that falsifier 2 called for; this comparison narrows the wound (a one-viewport rest register is now demonstrated for all three), it does not close it.

### 5. Determinism

All three pin the same way and all can produce byte-identical output twice: layout is a pure function of (presentation bytes, host stubs, focus SAID); ranks are longest committed path; ordering within rank is SAID-lexicographic; tiers/stack orders/lane assignments are discrete and rule-assigned; nothing is seeded, iterated, or time-dependent except the host-clock render moment, which is a declared host input. Arm C is deterministic *because* force-directed re-centering was declined — the one liberty the brief permitted that the conformance-corpus requirement argues against taking, since force layouts are non-deterministic unless seeded and mental-map-hostile even when seeded ([focus-context.md](../../research/prior-art/focus-context.md) §"Layout stability").

### 6. Print

Arm B: the rest board is an honest map; parameters need per-card expanded sheets (the print-flattening the composite already owns). Arm A: the rest frame is an index of one-line entries — it works as an index and carries less than B's rest board; same sheet obligation. Arm C is the interesting one: a static render has no focus and the mechanism defines its own degradation — with no `y`, `F` collapses to its API argument, so the print form is frame C1: the prominence budget alone deciding size, with no interactive residue. That is the strongest print answer of the three, and it is a defined consequence of the formula, not a special case bolted on.

### 7. Re-layout cost

Arm B and arm C change tier only: positions, ranks, and orderings are fixed functions of the presentation, so orthogonal ordering — the one mental-map property with a proof tradition — is preserved across every focus change, and no arm lets proximity carry meaning (the caps say so inside the renders: sizes are allocation, distances are packing, path length is read by counting cards). Arm A additionally *asserts* an order it does not mean: a pile is a total order and the diamond is a partial one, so the stacking sequence of items 05/06/07 is a layout artifact the render must actively disclaim — the only arm whose geometry fights its own captions. Animated transitions, if ever added, earn only the narrow spatial-reconstruction claim and carry the WCAG 2.1 SC 2.3.3 (AAA) disable obligation.

## Recommendation, with its evidence

**Adopt arm B as the spine, amended by arm C's API term as a second floor: budgeted cards floor at the mid form (150×72), everything else at 76×44. Retire arm A.**

- The stress board's largest per-card wound was that the floor holds states but not parameters, and two of three deformations degrade into six-point words. Frame C2 shows the mid-form floor repairing exactly that — policy values, corner-withdrawal, and the transparent region all survive off-focus — at a measured cost of ≈ 46% more column at this load (1,044 vs 716 px focused; 578 vs 322 at rest). The cost is real and the exhaustion analysis in Q4 says when it bites; at SC13's own scale it fits.
- The amendment is one rule, not a mechanism: it needs no distance term at all until renders get much larger, because `max(state_floor, focus_tier − hops)` with only two effective tiers *is* arm B plus a floor exception. Everything the focus+context literature indicts — distortion, magnification-coupled navigation, continuous shrink, force layouts — stays refused, and no comprehension claim is made anywhere.
- Arm A dies, and the reason is measurement, not the charrette's argument. The charrette refuted the pile on edges-attach-to-hidden-geometry; a sliver answers that completely (frame A2's focused card has both parents attached to visible geometry). What kills it: (1) dominance — a plain sliver spends 1.55× the area of a floor chip (5,184 vs 3,344 px²) to carry one line against the chip's three, because a card's width is indivisible while chips pack four across, so layering is taller than compression at rest (+34%) and at focus (+15%) while showing less; (2) linearization — a pile is a total order, the diamond is a partial one, and the geometry asserts a chain the captions must disclaim; (3) lane apparatus — five diamond edges needed four left-margin lanes that compete with the frontier gutter and grow with rank-skipping edges; (4) the sliver degrades the H2/H6 tier below even the floor's degraded form. Its two genuine wins — perimeter states read beautifully in a strip, and 288 px of run-room carries prose parameters the chip sheds — are both subsumed by the mid form, which has the same width-class run-room in its break row plus two more lines.

## What died, plainly

- **Arm A as a general mechanism.** Daniel proposed it, and the fair test was owed: the occlusion refutation does not apply to visible slivers, and the arm was built and measured rather than dismissed. It is dominated — more area per object for less content, plus the partial-order problem — and the recommendation retires it. What survives of it is a finding, not a form: perimeter-class states are the only card states that survive extreme vertical compression, which independently confirms the stress board's stale-break result and strengthens the case for perimeter-class floor glyphs for H6/H2 (still undesigned).
- **Naive DOI died before construction**, killed by the literature audit rather than by these mocks: additive Furnas scoring with continuous size, fisheye distortion, focus-driven magnification, and force-directed re-centering are all indicted by the eye-tracking, target-acquisition, and review evidence in [focus-context.md](../../research/prior-art/focus-context.md), and the Visual Thesaurus is no precedent because it is not DOI. What was built as arm C is the honest residue — a floor rule wearing Furnas's general form — and its value turned out to be exactly the part that is *not* fisheye.
- **Not solved here, still open:** the count-the-terminals residual (item 09) at any non-expanded tier — no arm's mechanism reaches graph-level state; the edge-of-viewport residue for large N (falsifier 2's wound, narrowed to a slope analysis, not closed); and every comprehension question, which remains the small-n probe's property (P9 — the armchair is disqualified, and nothing in these files claims otherwise).

## Coinages requiring review (this comparison's own)

The sliver grammar of arm A (retired with the arm, but the perimeter-survival finding stands); the mid form (150×72) as a budgeted-state floor — it is the stress board's frame-1 chip promoted to a defined tier, and its H6 corner-tick and H2 mini-region treatments at that size have exactly one exhibit each; the `max(state_floor, focus_tier − hops)` combining form and its domain restriction for undefined distance — consistent with Furnas's 2006 monotone-F generalization but original in the floor semantics and the unknowable-distance behaviour, for which the literature survey found no prior art at all. Treat each as a proposal with one exhibit behind it.

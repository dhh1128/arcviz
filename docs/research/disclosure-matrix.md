# The disclosure-state matrix

Phase 2B. This is the deliverable everything downstream depends on: the decomposition of "what state is this credential in?" into orthogonal axes, the per-cell statement of what a viewer knows / cannot know / would be lied to about by a naive renderer, the states that are indistinguishable from the artifact alone, and the rendering rules that fall out.

**Citation discipline.** Spec claims cite `spec/spec-body.md` line numbers in the vendored ACDC spec (`~/code/me/kswg-acdc-specification`, commit `651df33e`, verified byte-identical to upstream `main` for every section cited — see [acdc-inventory.md](acdc-inventory.md) "Sources read"; source key `[acdc-spec-vendored]`). Corpus claims cite [corpus-vlei-chain.md](corpus-vlei-chain.md) and [corpus-keripy-examples.md](corpus-keripy-examples.md) by section. Paper claims cite the keys already recorded in `refs/sources.papers-*.yaml` with their locators. Load-bearing spec passages (`spec-body.md:160-172`, `1747-1780`) were re-read directly for this document, not taken from the inventory's paraphrase. Reference-implementation claims (added in the 2026-09-05 revision — see Revision history) cite [keripy-verification.md](keripy-verification.md) and [keria-signify-surface.md](keria-signify-surface.md) by section; those documents are themselves primary-source reads of keripy/KERIA/signify-ts cited by `path:line`, and the load-bearing lines are re-quoted here rather than taken on the sibling document's word. ## (a) The axes

### The flattening this corrects

The project has circulated two lists as if they were one taxonomy: the spec's seven *disclosure variants* (Compact, Metadata, Partial, Nested Partial, Full, Selective, Bulk-issued Instance — `spec-body.md:1747-1774`), and a research-derived list of viewer-side conditions (*stale*, *erased*, *absent*, *unverified*, *not-yet-fetched*, plus AGENTS.md's *undisclosed* and *redacted*). These are not points on one scale. "Compact" is a property of which bytes are in hand; "erased" is a claim about why bytes are not in hand; "unverified" is a claim about what checks this viewer has run; "stale" is a claim about time. Flattening them produces states that are simultaneously true ("compact AND unverified AND stale") and states that look distinct but are the same observable ("erased" and "withheld" present identically — see §c).

### The five axes

The decomposition below differs from the candidate decomposition in the commissioning brief in one structural way: **"Form" (which spec disclosure variant the artifact is in) is not an axis.** Three arguments, each grounded in the spec itself:

1. **Form is not single-valued.** "All the Graduated Disclosure mechanisms MAY be used in combination" (`spec-body.md:1775`). A real artifact can be a bulk-issued instance whose `A` section is selectively disclosed while its rules section is compact — three "variants" at once. An axis whose values co-occur freely is not an axis; it is a vocabulary.
2. **Form does not change verification.** "a signature on any variant MAY be used to verify the Issuer's commitment to any other variant... This cross-variant Issuer commitment verifiability is an essential property" (`spec-body.md:1822`, quoted in [acdc-inventory.md](acdc-inventory.md) §5). There is one Issuer commitment; every variant is a view of it. So "which variant" carries no independent epistemic weight beyond what the per-unit holdings axis (H, below) already records.
3. **Two of the seven variants are not visibility degrees at all.** Metadata Disclosure is a *decoy commitment* — a differently-SAIDed artifact deliberately uncorrelatable with the real one (`spec-body.md:166-168`). Bulk-issued Instance Disclosure changes nothing about what is visible in this instance; it changes what disclosure *correlates to* across contexts (`spec-body.md:1773`). Putting these on a Compact→Full scale is precisely the category error being corrected.

The variants survive intact as *coordinates* on the axes below (mapping table at the end of this section), so nothing the spec names is dropped.

The five axes, with the observable each one carries:

| Axis | Name | Unit of application | What it records | Readable from the artifact alone? |
|---|---|---|---|---|
| **H** | Holdings | per addressable unit (see below) | what this viewer has in hand for that unit: content, commitment, reference, or nothing | yes (with the schema; see H-states) |
| **C** | Cause | per unit not fully in hand | *why* it is not in hand | mostly **no** — this is the out-of-band axis |
| **V** | Verification | per check, per artifact | which independent checks were run and what each returned | no — it is a record of this viewer's own acts |
| **T** | Time | a coordinate on every V claim, plus derived artifact states | as-of-when each claim holds; valid-then vs valid-now; staleness; reconciliation lag | no — requires clocks, event streams, and policy windows |
| **X** | Correlation | per artifact | instance identity (singular vs bulk-instance) and the perfect-correlator surface of what is in hand | partly — correlators are visible, instance-siblinghood is not |

**Addressable unit** (for axis H): any block or field the disclosure machinery treats independently — the top-level ACDC; each section (`s`, `a`, `A`, `e`, `r`); each nested sub-block of `a`; each element of the `A` aggregate array; each Edge and Edge-group; each Rule and Rule-group; each *referenced* artifact (an edge's far-node ACDC, a delegator's KEL, a registry's TEL, a schema). The uniform `d`+`u` mechanism applies at every one of these levels (`spec-body.md:91`; [acdc-inventory.md](acdc-inventory.md) §6), which is what makes one per-unit axis sufficient where the brief's candidate had separate "Form" and "Field epistemics" axes.

**Where each flattened observable lands:**

| Flattened term | Decomposition |
|---|---|
| absent | H (unit state H9, or H7 for a missing referenced artifact) |
| undisclosed / withheld | H2–H5 or H8 (commitment in hand, content not) × C (cause = holder choice — usually unknowable, see §c) |
| redacted / erased | same H states × C (cause = compliance erasure — usually unknowable, see §c) |
| not-yet-fetched | H7 × C (cause = viewer-side, knowable from the viewer's own fetch log) |
| unverified | V (checks unperformed or unperformable) — **not** an H state at all |
| stale | T (assurance window exceeded) — orthogonal to everything else |
| compact / partial / nested-partial / full / selective | H coordinates of the affected units |
| metadata | H6 (whole-artifact decoy commitment) |
| bulk-issued instance | X (instance identity), H unchanged |

**Orthogonality caveat, stated honestly.** C applies only when H ≠ content-in-hand, and T scopes V — so these are not a full Cartesian product. Orthogonal here means *measuring different things*, such that no value on one axis implies a value on another: a fully-held unit can be unverified; a verified artifact can be stale; a blinded unit can have any cause. That is the property the flattened lists lacked.

### The seven spec variants, decomposed (nothing dropped)

| Spec variant (`spec-body.md:1747-1774`) | Axis coordinates |
|---|---|
| Compact Disclosure | affected units at H2 or H3 (digest in hand); C typically "pending" — the spec frames it as commitment "that MAY be more fully disclosed later" (`:1761`), an *undisclosed-yet* state, not a redaction |
| Metadata Disclosure | whole artifact at H6; V: issuer-commitment checks *unperformable by design* (`:172`: "only cryptographic commitments from the Discloser are attached, not commitments from the Issuer") |
| Partial Disclosure | units at H3, movable to H1 by disclosing content + `u` (`:1765`) |
| Nested Partial Disclosure | H3 applied recursively, per branch, per level (`:1767`) |
| Full Disclosure | H1 throughout the disclosed scope — noting the spec's own warning that "Full" is scope-relative (`:1779`) |
| Selective Disclosure | disclosed elements at H1; undisclosed elements at H4 (SAID list in hand) or the whole section at H5 (AGID only) (`:1771`, `:661`) |
| Bulk-issued Instance Disclosure | H unchanged; X = bulk-instance (`:1773`) |

## (b) The matrix

Three columns per cell throughout: **knows** (the warranted claim), **cannot know** (the boundary of the warrant), **naive lie** (what an ordinary card design would wrongly imply — the point of the exercise).

### B1. Axis H — holdings, per addressable unit

| # | State | Viewer **knows** | Viewer **cannot know** | **Naive lie** |
|---|---|---|---|---|
| H1 | **Content in hand** — the unit is expanded; labels and values present | The exact bytes; can recompute the unit's `d` and check it against every enclosing commitment; absence of an optional field *inside* an expanded block is issuance-time absence, committed by the SAID | Whether the content is *true* — authenticity ≠ veracity ([avv2025-orthogonality], `authenticity-vs-veracity.md:35`); whether anything else exists beyond this unit | Visible ⇒ fine. A card that renders values with no verification channel implies the display itself vouches for them; and it renders the *absence* of sibling data as nonexistence (see H9, X) |
| H2 | **Unblinded commitment** — bare SAID in hand for a block whose schema reserves no `u` (or whose `u` is absent) | Content-identity commitment; the block's shape via schema; the content is verifiable if later provided; crucially, the content **may be discoverable now** by rainbow/dictionary attack over the schema's value space, and the SAID is "a fixed point of correlation, potentially to the ACDC field values themselves in spite of non-disclosure" (`spec-body.md:160`) | The actual content (without guessing); the cause (axis C) | The gravest one on this axis: rendering an unblinded digest with a "private"/"redacted" treatment asserts a protection that does not exist. The spec's own verdict: such an ACDC "SHOULD be considered a public (non-confidential) ACDC" (`:160`) |
| H3 | **Blinded commitment** — bare SAID in hand, committed block carries a high-entropy `u` (per schema), `u` not disclosed | Commitment; shape via schema; content is computationally hidden — an adversary "is not able to discover the remaining contents... in a computationally feasible manner" (`spec-body.md:164`); the SAID is *not* a correlator to field values "unless and until there has been a disclosure" (`:164`) | Content; cause (withheld? erased? pending? — §c pair 1 and 3); whether disclosure will ever be offered | Rendering it as an error, a loading state, or empty. Also the inverse of H2's lie: conflating H3 with H2 under one "hidden" icon erases the only privacy distinction the format actually delivers |
| H4 | **Hidden aggregate element** — a bare SAID at some position in a disclosed `A` array | The count of elements; membership is provable if later given content+`u` ("Membership in the set can be verified against a set of SAIDs, one from each element", `:1771`); **nothing else — not even labels**, because "the field labels for a given block only appear within that blinded block" (`:694`) | Labels, values, which schema candidate each element instantiates; position tells nothing — the schema's `anyOf` order "is not correlated to the actual order of appearance... This prevents inference based on location" (`:694`) | Two lies. (1) Rendering hidden elements with candidate labels enumerated from the schema's `anyOf` — manufacturing information the format deliberately withholds. (2) Rendering them positionally aligned to the schema, implying an order-to-meaning mapping the spec explicitly severed |
| H5 | **Aggregate fully compact** — only the AGID in hand as the `A` field's value | A commitment to *some* list of elements exists | The count, the labels, the values — everything below the AGID. And the AGID is "an aggregate, AGID, (Aggregate ID) not a SAID" (`spec-body.md:661`) — it is a digest over an ordered list with a dummied placeholder (`:712-720`), not a content-address of a block | Rendering the AGID as a SAID pill. An entviz pill asserts content-identity of a block ([acdc-mtc-said-vs-membership]); an AGID is a different commitment object with a different expansion procedure, and dressing it as a SAID misstates what a match would prove |
| H6 | **Metadata decoy** — an artifact whose top-level `u` is present but *empty* (`spec-body.md:166`) | The Issuer, Schema, provenanced Edges, and Rules of a yet-to-be-disclosed private ACDC; the Discloser's commitment to this metadata; the real ACDC's `d` "will necessarily be different" (`:166-168`), by design | The real ACDC's SAID or attribute content; and — the sharp part — the Issuer stands behind *nothing yet*: "only cryptographic commitments from the Discloser are attached, not commitments from the Issuer" (`:172`) | Rendering a metadata ACDC with the visual authority of an issued credential — issuer name, schema title, edges drawn — when the issuer has committed to none of it as presented. This is a pre-contractual sketch wearing a credential's clothes |
| H7 | **Reference in hand, artifact not** — an edge's `n` SAID names a far node not in the payload; a `di` field names a delegator whose KEL is absent | The identity (SAID/AID) of what is missing; that the near artifact commits to it; verification of everything that depends on it is *unperformable with material in hand* (axis V) | Anything about the missing artifact's content or validity; the cause splits — viewer-side (not fetched / fetch failed: knowable from the viewer's own session log) vs remote-side (never provided: not knowable from the artifact) — §c pair 4 | Omitting the dangling edge or the named delegator, so the chain renders shorter and *more complete* than it is. The real vLEI chain has exactly this hole: "the root `EDP1vHcw...`'s KEL... is absent entirely. The chain's delegation claims cannot be fully verified from this payload alone" ([corpus-vlei-chain.md](corpus-vlei-chain.md) §3). Incomplete evidence is a normal state, not an error state |
| H8 | **Reference hidden** — a Compact Private Edge: the edge block is replaced by its SAID with a `u` inside, so even the far node's identity is withheld | An edge exists in a named schema slot; the presenter has made "a verifiable commitment to the ACDC attached to the Edge without disclosing any details of that ACDC, including the ACDC's SAID" (`spec-body.md:1165`) | Where the edge points; everything about the far node | Dropping the edge from the graph entirely. A DAG with a committed-but-blinded edge has different topology than a DAG without it, and hiding the hidden edge hides that the holder is withholding a relationship |
| H9 | **Nothing** — no field, no digest, no reference | If the *enclosing* block is at H1: this artifact, as issued, has no such field — absence is committed by the enclosing SAID and is an issuance-time fact. If the enclosing block is not at H1: not even that | That the information does not exist elsewhere; that the party lacks some other credential. The negative claim is a claim about a corpus the viewer does not have ([PLAN.md](PLAN.md), correlation-honesty principle), and EUDI *mandates* the ambiguity at whole-credential level: denial "SHALL behave towards the Relying Party as if the attestation did not exist" ([arf-topic-d-embedded-disclosure-policies] REQ 4, [prior-art/wallets.md](prior-art/wallets.md) §1) | Rendering absence as zero, as false, as "none", or as a withheld field. And the exhaustive-looking empty state: "no linked credentials found" reads as a fact about the world when it is a fact about the payload |

**A leakage asymmetry the matrix must carry (H1 interacting with H3 vs H4).** Expanding *any* sub-block of an `a` (attributive) section "exposes, at the very least, the labels of other fields in its enclosing block" (`spec-body.md:1777, 1779`), whereas disclosing an `A` element exposes nothing about siblings, "including their labels" (`:1777`). So after one field of an `a` block is disclosed, its still-hidden siblings are in a distinct sub-state — **label known, value hidden** — that exists nowhere in the `A` mechanism. A renderer that shows both as generic "hidden fields" understates what the verifier already learned in the `a` case (the holder may not realize the labels leaked) and overstates it in the `A` case. This is the mechanism-level difference the corpus makes concrete: the guardianship example reveals one boolean age flag "and nothing about which other thresholds hold — the aggregate form exists precisely so *which* flags are asserted stays hidden... unlike a labeled attribute set where a revealed field advertises its own name" ([corpus-keripy-examples.md](corpus-keripy-examples.md) §(b)2).

### B2. Axis C — cause of a unit not being fully in hand

The values, split by who could know them:

| Cause | Knowable by this viewer? | Basis |
|---|---|---|
| pending-graduated — commitment made, fuller disclosure on offer in an ongoing exchange | only from exchange state (IPEX apply/offer/agree/grant), not from the artifact | Compact Disclosure "MAY be more fully disclosed later" (`spec-body.md:1761`); the exchange grammar is IPEX ([corpus-keripy-examples.md](corpus-keripy-examples.md) §(b)1, disclosure-path `dp` machinery) |
| withheld-by-choice — holder decided not to disclose, this presentation | **no** — presents as a bare digest | [keri-primer-erasure-vs-hash], `keri-primer.md:223`; §c pair 1 |
| erased-for-compliance — "the payload is destroyed. The hash remains in the log to preserve the integrity of the chain" | **no** — presents identically to withheld | same source; §c pair 1 |
| viewer-not-fetched / fetch-failed — the far artifact was never retrieved, or retrieval failed | **yes** — from the viewer's own session history, never from the artifact | **Inference** from the structure of the problem; no source assigns this state, which is itself evidence it is viewer-local |
| never-provided — the presenter did not include the referenced artifact and no fetch route exists | no — indistinguishable from a fetch the viewer didn't attempt, absent a fetch log; §c pair 4 | [corpus-vlei-chain.md](corpus-vlei-chain.md) §3 (the absent root KEL) |
| never-issued — the field was absent at issuance | yes, iff the enclosing block is at H1 (committed absence) | SAID commits the enclosing map (`spec-body.md:20`) |

**Knows / cannot know / naive lie for the axis as a whole:** the viewer knows, at most, its own side (fetch history, exchange state) plus committed issuance-time absence; it cannot know the remote party's reason from the artifact, ever, for the withheld/erased/never-provided family; and the naive lie is any cause-specific label — "redacted", "withheld", "deleted" — attached without host-supplied evidence. Each of those words is an accusation or an excuse the artifact does not carry.

### B3. Axis V — verification, a vector of independent checks

Each check has a four-valued outcome — **pass / fail / unperformed / unperformable-with-material-in-hand** — plus a T-scope (§B4). The last two outcomes are different states and must render differently: *unperformed* is the viewer's choice or laziness — or, far more often, the honest description of a check whose result did not survive; *unperformable* is a fact about the evidence (the vLEI root-KEL hole makes delegation-to-root unperformable, not failed).

**Amended 2026-09-05, from the keripy audit ([keripy-verification.md](keripy-verification.md)): "unperformed" is the *default* truth for most cells of a merely-retrieved credential, not an edge case.** Eight of the nine checks in the reference implementation are verify-or-throw gates whose pass is recorded only implicitly as "the object exists"; "there is no API, stored record, or status object of the shape 'for credential X, checks 1-9 were {pass, fail, unperformed, unperformable}' anywhere in `src/keri/`" ([keripy-verification.md](keripy-verification.md) §(d)). The one exception is revocation: `Tever.vcState(vcid)` (`src/keri/vdr/eventing.py:1144-1192`) is "the one genuinely separable, re-queryable check" (§(a) check 8). So a renderer handed a credential from storage, with no freshly-computed vector from its host, must show checks 1–7 and 9 as unperformed *from its own point of view* — not because nothing happened, but because nothing survived the moment it ran. This strengthens rather than weakens the vector framing: the substrate itself does not track the distinctions a single "verified" badge would claim to summarize.

An original design premise of this section is hereby weakened in one specific place. This document treated fail vs unperformed as always distinguishable in principle. **For checks 6 and 7, against a stock keripy substrate, they are not: those checks can never honestly report "fail" — only "not-pass".** `verifyChain` "returns `None` both when the far node genuinely fails a constraint (e.g. `op == 'I2I' and issuer != farIssuee`, `verifying.py:478-479`) and when the far node simply is not in the store yet (`verifying.py:418-420,471-472,475-476`)", and its caller treats both identically — the same `MissingChainError`, the same escrow ([keripy-verification.md](keripy-verification.md) §(a) check 6; the full pair is §c pair 10). A host built directly on keripy "cannot honestly report 'fail' for these two checks at all today; it can only report 'unperformed/unperformable' or 'pass'" (§(e)). Rule 2 carries the rendering consequence.

| Check | A **pass** warrants | A pass does **not** warrant | **Naive lie** |
|---|---|---|---|
| SAID self-consistency (recompute `d` over the unit) | Content identity: "the disclosed view corresponds to a specific underlying claim" ([acdc-mtc-said-vs-membership], `acdc-and-mtc.md:48-51`) | Freshness, membership in any audited set, timing: "A Merkle inclusion proof establishes placement in a history. A SAID establishes identity of content" ([acdc-mtc-said-vs-inclusion-summary], `:86`) | A SAID pill styled as a "verified" badge — borrowing currency/endorsement connotations the digest does not carry |
| Schema conformance | The artifact instantiates the committed shape | Anything about values' truth or provenance | — |
| Signature validity (bare) | "someone controlling a private key processed some bytes" ([signauthor2026], `sign-author.md:42-50`) | *When* relative to key compromise — "simple signatures are difficult to sequence relative to a compromise or revocation event" ([was.md:18 via papers-acdc.md](prior-art/papers-acdc.md)); authorship, endorsement, intent | The single green check. It collapses "valid now" and "valid then" into one signal — the "pyrrhic victory" (`was.md:51-52`) |
| KEL anchoring (digest present in issuer's KEL at seq N, event properly signed/witnessed) | The signing act is *sequenced* against key state — the retrograde-attack closure ([keri-primer-verifier-steps], `keri-primer.md:196-200`) | Issuer honesty; that the KEL consulted is the only KEL (duplicity, below) | Rendering anchored and bare signatures with the same glyph — the two are different claims and the papers require them visually distinguishable ([papers-acdc.md](prior-art/papers-acdc.md) §(c)3) |
| Delegation chain (each `dip`/`drt` anchored in its delegator's KEL, up to the root) | Authority derivation *as far as the KELs in hand reach* | Anything beyond the deepest KEL held — in the real chain this check is **unperformable past the first delegation tier** ([corpus-vlei-chain.md](corpus-vlei-chain.md) §3) | "Delegated ✓" with no reach annotation, implying the root was checked when it was not present to check |
| Edge constraints (`I2I`/`NI2I`/`DI2I` identity relations; far-node SAID match; far-node schema, incl. the edge's own `s` override) | The stated relation holds between near-issuer and far-issuee, per the operator *including the default-injection rule* (`spec-body.md:1197-1201`) | **Validity propagation.** Whether a bad far node invalidates the near node is EGF-dependent — the spec says "MAY", not "MUST", and "the actual logic... is EGF-dependent" (`spec-body.md:1112-1116`; [acdc-inventory.md](acdc-inventory.md) OQ4). Also: an edge transfers no attribute values and, absent `I2I`/`DI2I`, no identity relation at all (`:1207`; inventory §3) | Chain-level status roll-up: one badge for the whole DAG. Every node's status is independent ([ev-life-verifier-checklist], `ev-life.md:85-86`), and a roll-up either encodes an EGF rule as if it were spec-given or invents one silently |
| Issuer bona fides (the qualifying chain: e.g. QVI credential behind the LE credential) | The issuer's authority claim is itself provenanced through verifiable ACDCs ([sdjwt-acdc-chaining-registries], `sdjwt-acdc.md:65`) | That any claim is *true* — "tamper-evident provenance of the assertion graph, not that any given upstream claim is factually true" ([papers-acdc.md](prior-art/papers-acdc.md) §Q2, on `keri-primer.md:215`) | "Verified issuer" as an endorsement. The chain makes credibility *traceable*, not certified |
| Revocation reconciliation (TEL replay) | "not revoked *as of the events in hand*" — revocation is "expressed as events... reconciled over time"; "the verifier's task is to reconcile events, not to query a live service" ([acdc-mtc-revocation-reconciled], `acdc-and-mtc.md:54,134`) | Not-revoked simpliciter. The vLEI payload contains no `rev` events — which proves only that none were *in the capture* ([corpus-vlei-chain.md](corpus-vlei-chain.md) §3); §c pair 6 | "Active" / "Not revoked" with no as-of. This is the OCSP mental model imported into a system built to reject it |
| Duplicity (watcher cross-check of witnesses) | "no duplicity detected by the witnesses/watchers consulted" — KERI is "duplicity-evident rather than duplicity-resistant" ([wtbo-duplicity-evident-not-resistant], `wtbo.md:113`) | That duplicity does not exist; a dishonest watcher "can... stay silent" (`wtbo.md:109-111`); §c pair 7 | A witness count or witness badge styled as endorsement — "A witness makes no such assertion. A witness simply stores and serves events" ([keri-primer-witness-not-ca], `keri-primer.md:153`) |

**The axis-level naive lie** is the vector collapsed to a scalar: one checkmark, one color, one word "verified." Every shipped wallet audited does exactly this — Apple and Google collapse "cryptographically valid" and "issuer is trustworthy" into one word ([prior-art/wallets.md](prior-art/wallets.md) §"What we should refuse"), and every audited codebase passes a backend chip through unexamined ([prior-art/local-codebases.md](prior-art/local-codebases.md) §"Interfaces"). A checkmark not backed by a check the software performed "is a UI element, not a credential" ([hardman-proga-uielement], `prog-a.md`).

### B4. Axis T — time

| State | Viewer **knows** | Viewer **cannot know** | **Naive lie** |
|---|---|---|---|
| as-of scope on every V pass | Each check passed against a specific event horizon (KEL seq, TEL event, wall-clock of the run) | Anything past that horizon | An undated badge, which silently means "valid at some point" while reading as "valid now" |
| valid-then vs valid-now | These are *two different queries the substrate can answer*: "It must be possible to distinguish what was valid then from what is valid now" ([telco-historical-vs-present-validity], `telco-ev-reqs.md:154`); the capability is real because anchored signatures sequence events ([x509prob-certs-no-audit-trail], `x509-prob.md:111-112`) | — | Rendering only the valid-now answer, discarding historical provability — "throwing away a real capability of the substrate it renders" ([prior-art/papers-other.md](prior-art/papers-other.md)) |
| stale — the assurance window has lapsed | The last reconciliation/reconfirmation is older than a policy threshold (the LEI's LAPSED status is the named precedent: data "has not been reconfirmed within a specified period" [hardman-proga-lapsed]) | Whether anything actually changed in the interim | The one most likely to render as *fine*: "a credential that was valid when captured looks identical to one valid now" ([prior-art/papers-intent.md](prior-art/papers-intent.md) §(c)) |
| unreconciled — events are known or suspected to exist that the viewer has not replayed | Its own replay position | What the unreplayed events say | Treating replay-lag as "not revoked." Freshness assumptions "must be explicit" ([telco-revocation-freshness-explicit], `telco-ev-reqs.md:164-166`) |

**Correction (2026-09-05): the valid-then-vs-valid-now row is implementation-attested, not only paper-attested.** As first written, this axis rested the "two different queries the substrate can answer" claim on the papers alone, and the Phase 2D-b survey initially concluded no surface serves TEL event history. That conclusion was wrong at the scope it implied ([keria-signify-surface.md](keria-signify-surface.md), Correction section): keripy's **witness** exposes `GET /query?typ=tel` with `reg` (registry prefix) or `vcid` (credential SAID) — `QueryEnd`, `src/keri/app/indirecting.py:1191`, mounted in `setupWitness` at `indirecting.py:104` — serving `reger.clonePreIter()`, "the whole event stream for that prefix", as CESR: "genuine event history, not a state snapshot". It is live in `WebOfTrust/keripy` `main` at 2.1.0-dev0. Additionally, the V2 registry layer addresses TEL events **by sequence number** (`RegistryStore.seqEvent(regk, sn)`, `src/keri/acdc/registering.py`), and `WebRegBaser` "sets up **browser** sub databases for public ACDC registry TELs" (`webregbasing.py`) — IndexedDB — so valid-then-vs-valid-now may become *re-performable client-side* rather than taken on an agent's word. What is **not** fixed: the KERIA agent API still exposes only latest-state snapshots (`status`, `credentials().state()` — [keria-signify-surface.md](keria-signify-surface.md) §(b), §(d) pair 6), so whether this axis is servable in practice depends on **which surface the host talks to** — a witness or browser-local registry store serves it; the KERIA agent surface, today, does not.

**Decided 2026-09-05 (was a flagged inference):** the staleness threshold is **host-supplied, per credential** — not owned by arcviz and not a single global window, because "different credentials may have different revocation-freshness profiles" ([PLAN.md](PLAN.md) decisions, second set), presumably keyed by schema, registry, or governance framework — consistent with the LAPSED precedent's governance-defined threshold ([hardman-proga-lapsed]). Where no policy is supplied for a credential, "no freshness policy supplied" is its own visible state, not a silent default. §f question 2 is closed by this.

## (c) Indistinguishable states

States not separable from the artifact alone — plus one (pair 10) not separable from the reference *substrate* either. For each pair: the observable they share, and the out-of-band information that would separate them — which is, collectively, the interface arcviz needs from its host. The honest rendering names the ambiguity; it never picks a side.

1. **Erased-for-compliance vs withheld-by-choice.** Both present as a bare digest with no recoverable payload: "the payload is destroyed. The hash remains in the log to preserve the integrity of the chain" ([keri-primer-erasure-vs-hash], `keri-primer.md:223`; flagged as a genuine spec-level ambiguity in [prior-art/papers-acdc.md](prior-art/papers-acdc.md) §(e)1). **Separator:** an attested statement of cause — e.g. a dossier Annotation Edge marking the artifact's effective state in a later version ([acdc-inventory.md](acdc-inventory.md) §7, "Verifiers MUST process the dossier by traversing the graph to resolve the 'effective state'"), or issuer/holder metadata the host supplies. **Host interface: attested-cause metadata per unit, with its own provenance** (an unattested cause string is a claim, not a fact, and should render as such).
2. **Default vs explicit edge operator.** Two vLEI edges omit `o` (defaulting to `I2I` per `spec-body.md:1197-1201`) and one writes `I2I` explicitly, for the identical relationship ([corpus-vlei-chain.md](corpus-vlei-chain.md) §2). **Separator:** none is needed — the states are semantically identical, and the honest rendering is *identical rendering*, with the syntactic difference visible only in a raw-bytes view. This pair is in the list because its resolution is opposite to every other pair: here the renderer must *suppress* a visible difference rather than surface an invisible one, and "specified vs unspecified" must never become a badge.
3. **Compact-pending vs withheld-final.** A bare SAID may be an interim state in a graduated exchange ("MAY be more fully disclosed later", `spec-body.md:1761`) or the holder's final answer. **Separator:** the exchange state — IPEX apply/offer/agree/grant position and the offer's disclosure paths (`dp`, [corpus-keripy-examples.md](corpus-keripy-examples.md) §(b)1,3). **Host interface: negotiation context, when the render happens inside an exchange.**
4. **Never-provided vs not-fetched vs fetch-failed** (for an H7 referenced artifact). From the artifact, all three are one state: the far thing is not here. **Separator:** the viewer's own session history — did this viewer attempt retrieval, and what happened. Two are self-knowledge the host/component already holds; only never-provided-vs-unfetchable remains genuinely open after logging. **Host interface: a fetch/attempt log per referenced SAID.** (Fetching itself is an intent boundary and a disclosure to third parties — [prior-art/papers-intent.md](prior-art/papers-intent.md) affordance 4 — so the log will often legitimately read "not attempted.")
5. **Blinded vs unblinded commitment (H3 vs H2) when the schema is not in hand.** The distinction rests on whether the committed block reserves a `u` (`spec-body.md:160,164`), which is read from the schema; with the schema itself compact or unresolvable, a bare SAID is just a bare SAID. **Separator:** the schema. **Host interface: schema resolution — noting that resolving it over the network is itself a correlating fetch (pair 4's caveat applies).** Until resolved, the honest state is "hidden; protection unknown."
6. **Not-revoked vs revoked-beyond-the-horizon.** Absence of revocation events in the material in hand ([corpus-vlei-chain.md](corpus-vlei-chain.md) §3) is consistent with both. **Separator:** fresher TEL events; never fully separable — only the as-of horizon moves ([acdc-mtc-revocation-reconciled]). A concrete source of fresher events exists in the substrate: the witness TEL-replay endpoint (`GET /query?typ=tel` — §B4 correction), though not on the KERIA agent surface. **Host interface: event-stream updates plus an explicit freshness policy — now decided to be host-supplied per credential, with "no policy supplied" a visible state** ([telco-revocation-freshness-explicit]; [PLAN.md](PLAN.md) decisions 2026-09-05, second set).
7. **No-duplicity-detected vs no-duplicity-exists.** Structurally never separable: KERI is duplicity-*evident*, and detection is relative to the witnesses/watchers consulted ([wtbo-duplicity-evident-not-resistant], `wtbo.md:109-113`). **Separator:** none complete; consulting more independent watchers shrinks the gap without closing it. The rendering must therefore always scope the claim ("none detected by N watchers"), never state the universal.
8. **Non-possession vs declined presentation** (whole-credential level). Deliberately indistinguishable outward: the wallet "SHALL behave towards the Relying Party as if the attestation did not exist" ([arf-topic-d-embedded-disclosure-policies] REQ 4, via [prior-art/wallets.md](prior-art/wallets.md)). **Separator:** none, by design of the presenting ecosystem — and arcviz must not imply one exists. This is the strongest external confirmation that H9's "cannot know" column is load-bearing.
9. **AGID vs SAID, as strings.** Both are CESR digest primitives; the derivation code names the algorithm, not the commitment kind. What makes a value an AGID is its structural position (the compact value of an `A` field) and the schema — "the value of a compact variant of the selectively disclosable Aggregate section is an aggregate, AGID, (Aggregate ID) not a SAID" (`spec-body.md:661`). **Separator:** structural/schema context, which the renderer must consult before choosing a pill treatment. **Inference:** that the strings are otherwise indistinguishable follows from AGID's construction as an ordinary digest over the serialized list (`:712-720`); no spec sentence states it outright. Flagged.
10. **Edge-constraint failed vs far-node-not-yet-checkable** (added 2026-09-05 — the one pair found in the implementation rather than the spec, and indistinguishable from the *substrate* rather than from the artifact). In keripy, `Verifier.verifyChain` "returns `None` both when the far node genuinely fails a constraint (e.g. `op == 'I2I' and issuer != farIssuee`, `verifying.py:478-479`) and when the far node simply is not in the store yet (`verifying.py:418-420,471-472,475-476`)"; `processCredential` routes both to the same `MissingChainError` and the same escrow table (`reger.mce`, `verifying.py:187-191`), and expiring escrows are "simply removed and logged" with "no persisted distinction between 'the far node arrived and the constraint was violated' and 'the far node never arrived at all'" (`verifying.py:318-361`; all quotes [keripy-verification.md](keripy-verification.md) §(a) check 6, §(c); source `src/keri/vdr/verifying.py:400-490`). The reference implementation therefore cannot distinguish *failed* from *not-yet-checkable* for edge constraints — or for issuer bona fides, which it implements only as a special case of the same code path (§(a) check 7). **Separator: none exists in the substrate today.** A host could create one only by instrumenting or re-implementing `verifyChain`'s internals so the two `None` paths report differently — nothing in keripy does this bookkeeping ([keripy-verification.md](keripy-verification.md) §(d)). Until a host does, the honest outcome space for checks 6 and 7 is {pass, not-pass}, per the §B3 amendment and Rule 2.

## (d) Rendering rules

Written to be testable: each rule names a violation a reviewer can look for. "Renders distinctly" means distinguishable by discrete symbol/shape/text — never by color alone ([PLAN.md](PLAN.md) principle: security-relevant state rides on discrete symbols; [amp-diff-principle-5]).

- **RULE 1 — no shared rendering across H-states.** Each of H1–H9 renders distinctly from every other and from any "fine" default. *Test:* produce fixtures for all nine; any two visually identical cells (ignoring content text) fail. In particular H2 vs H3 (guessable vs blinded), H4 vs H5 (count known vs unknown), H7 vs H9 (missing referent vs committed absence) must be pairwise distinct.
- **RULE 2 — verification renders as a vector, never a scalar.** Every check in §B3 gets its own indicator with four distinguishable outcomes: pass, fail, unperformed, unperformable. *Test:* find any single element whose presence summarizes more than one check; find any rendering where unperformed and unperformable share a glyph; find any rendering where unperformed is invisible (absence of a positive must not read as fine — the COIA rule: "An application MUST NOT render an absent flag as a positive assurance", [prior-art/local-codebases.md](prior-art/local-codebases.md) §4). *Amended 2026-09-05, per the keripy audit — the rule survives and is reinforced, with two changes.* (a) **Unperformed is the default truth, not an edge case**: since eight of nine checks leave no retrievable record past the moment they ran (§B3 amendment; [keripy-verification.md](keripy-verification.md) §(d)), a credential merely retrieved from storage renders with most cells at unperformed unless the host re-ran verification at render time or instrumented its own ingestion to persist a vector; the only substrate-re-queryable cell is revocation (`Tever.vcState`). The honest claim store presence itself supports is R0's — "the substrate's ingestion gate did not reject this" — never a pass on the other cells. (b) **The host interface must let a host declare a check's outcome space degraded to {pass, not-pass}**, and a renderer must not claim to distinguish fail from unperformed for a check where its host's substrate cannot make that distinction — on stock keripy that is checks 6 and 7, which can never honestly report "fail" (§c pair 10). *Additional tests:* a fixture retrieved from a bare store rendering anything other than unperformed for checks 1–7 and 9 without a host-supplied vector fails; a rendering that shows "fail" for an edge-constraint or issuer-bona-fides check backed by an undegraded stock-keripy host fails.
- **RULE 3 — every positive verification claim carries a visible as-of scope.** *Test:* find a pass indicator with no reachable as-of; find a revocation state phrased as "not revoked" rather than "no revocation as of ⟨horizon⟩"; find a duplicity state phrased without naming the consulted-watcher scope.
- **RULE 4 — stale is a first-class symbol.** When the as-of scope exceeds the freshness policy — host-supplied, **per credential**, per the 2026-09-05 decision ([PLAN.md](PLAN.md), second set) — a distinct staleness marker appears without user action; a credential for which the host supplied no policy renders "no freshness policy supplied" as its own state, never a silent default. *Test:* age a fixture past the threshold and diff the render; no visible change fails. Render two credentials under different per-credential policies; a single global threshold applied to both fails. Render a no-policy fixture; anything other than a visible no-policy state fails.
- **RULE 5 — cause renders as unknown unless attested.** For any unit at H2–H5/H8, the cause label is "unknown" unless the host supplied attested cause metadata, in which case the label carries the attestation's own provenance. *Test:* find "redacted", "withheld", "deleted", or "private by choice" on any cell whose cause input is empty.
- **RULE 6 — the `a`/`A` leakage asymmetry is drawn.** A hidden sibling in a partially-disclosed `a` block renders as *label-known-value-hidden*, showing the leaked label; a hidden `A` element renders as an opaque element with no label, positioned without schema alignment; a fully-compact `A` renders with count unknown. *Test:* R2 fixture showing any candidate label on a hidden element fails; R3 fixture hiding the leaked sibling labels fails.
- **RULE 7 — an AGID is never rendered as a SAID.** No SAID pill, no content-address affordance, on an `A`-compact value; its treatment names it an aggregate commitment. *Test:* R2/R4 fixtures; an entviz pill on the AGID fails.
- **RULE 8 — H2 never renders with a privacy-asserting treatment.** An unblinded commitment renders as "collapsed, contents recoverable/guessable", never with the lock/private/blinded treatment reserved for H3. When the schema is unavailable (§c pair 5), the treatment is "hidden; protection unknown", distinct from both. *Test:* three fixtures (H2, H3, schema-unresolved); fewer than three distinct treatments fails.
- **RULE 9 — default and explicit `I2I` render identically.** The operator badge shows the *effective* operator per the default-injection rule (`spec-body.md:1197-1201`); syntactic presence of `o` is visible only in the raw view. *Test:* render vLEI edges `le` (implicit) and `auth` (explicit); any visible difference outside raw bytes fails.
- **RULE 10 — missing referents render as holes, not trimmed edges.** An H7 unit (dangling `n`, absent delegator KEL) appears in the graph as an explicitly-unresolvable node, and every check it blocks reports unperformable with the blocking SAID named. *Test:* the vLEI fixture must show the root delegator; a 3-tier render of the 4-tier delegation, or a "delegation ✓" without reach, fails.
- **RULE 11 — no chain-level verdict roll-up.** Per-node status is per-node; any aggregate view labels itself as arcviz's own EGF-default rule, not spec-derived (validity propagation is EGF-dependent, `spec-body.md:1112-1116`), and remains overridable by the host. *Test:* find an unlabeled whole-chain badge.
- **RULE 12 — a metadata ACDC renders as issuer-uncommitted.** H6 artifacts carry a persistent, non-dismissable marker that no issuer commitment attaches as presented (`spec-body.md:172`). *Test:* R5 fixture rendered with the same authority chrome as an issued credential fails.
- **RULE 13 — no negative claims, anywhere.** Empty results, absent fields, and unlinked identifiers render with in-this-material scoping ("none *in what was presented*"); nothing renders as exhaustive. *Test:* find an empty state readable as "does not exist" ([hardman-wbca-negative]; §c pair 8).
- **RULE 14 — correlators are surfaced, not manufactured.** Identical SAIDs/AIDs *within the rendered material* render identically (the entviz pill is a correlator-surfacing device by design — [PLAN.md](PLAN.md)); residual correlators of a partially-disclosed artifact are enumerable on demand; but no join is drawn across separately-loaded presentations except as an explicit, distinctly-styled, logged act ([prior-art/papers-intent.md](prior-art/papers-intent.md) affordance 7). *Test:* load two presentations sharing an AID; a silently-drawn cross-presentation edge fails; an inferred edge sharing a disclosed edge's stroke fails.
- **RULE 15 — static output degrades honestly.** Print/screenshot/export renders every V indicator as a historical record ("checked ⟨scope⟩ by ⟨tool⟩"), never as live state, and carries what a re-verifier needs (SAIDs, as-of horizons). *Test:* diff live vs print CSS media output; identical verification chrome fails. (No audited ecosystem designed for this moment at all — [prior-art/wallets.md](prior-art/wallets.md) §5 — so this rule is arcviz's own, flagged as new per [PLAN.md](PLAN.md)'s affordance-scope decision.)

## (f) Open questions

Logged rather than decided, per the brief. Questions since closed by recorded decisions are marked **Closed** in place, keeping their numbers so cross-references stay valid.

1. **Is there, or should there be, an ecosystem convention for attesting erasure?** §c pair 1's separator (attested cause) has a dossier-spec mechanism (Annotation Edges) but no ACDC-level convention. Already put to Daniel as [prior-art/papers-acdc.md](prior-art/papers-acdc.md) §(e)1; the host-interface shape in §c is this document's proposal, not an answer.
2. **Who owns the staleness threshold?** **Closed 2026-09-05:** the host supplies it, **per credential** — different credentials have different revocation-freshness profiles, so the interface cannot be a single global window; a credential with no supplied policy renders "no freshness policy supplied" as its own visible state ([PLAN.md](PLAN.md) decisions 2026-09-05, second set; §B4, Rule 4 updated accordingly).
3. **What may the renderer claim about revocation "freshness"?** **Rewritten 2026-09-05.** An earlier version of this question claimed a tension between "real-time status checks" ([keri-primer-real-time-status], `keri-primer.md:269`) and "reconciled over time" ([acdc-mtc-revocation-reconciled], `acdc-and-mtc.md:134`), unresolved between Daniel's own papers. **That claim is retracted: both passages were read directly on 2026-09-05 and they do not conflict** — the primer's "real-time status checks without privacy leaks" compares against X.509/OCSP (checking costs no privacy), while `acdc-and-mtc.md` compares against Merkle Tree Certificates and describes the *mechanism*, event reconciliation rather than a live query; achievable currency and the means of achieving it are not competing claims ([PLAN.md](PLAN.md) decisions 2026-09-05, second set). The "no revocation as of ⟨horizon⟩" rule (Rule 3) stands on the simpler ground that reconciliation has a horizon **by construction**: "Freshness here is about continuity rather than immediacy" (`acdc-and-mtc.md:132`), so a viewer knows only as much as the events it has replicated. What remains open is only how much fresher a horizon a given deployment can reach — a question about surfaces (§B4 correction), not about the papers.
4. **AGID composition into the top-level SAID** ([acdc-inventory.md](acdc-inventory.md) OQ5) — blocks confident rendering of H5's relationship to the enclosing artifact's identity; needs a keripy reference-implementation check before Rule 7's treatment is finalized.
5. **`E1E`** ([acdc-inventory.md](acdc-inventory.md) OQ1) — not in the published spec but load-bearing in both guardianship worked examples, where a pre-#1527 verifier *wrongly rejects* it. **Closed 2026-09-05:** unknown operators render as **unevaluated, never as invalid** — "unknown operator, constraint unevaluated," the `unperformable` outcome on axis V; keripy's coerce-and-reject behavior is the naive alternative those same worked examples criticize ([PLAN.md](PLAN.md) decisions 2026-09-05, second set). The provisional lean logged here is confirmed as the decision.
6. **Does the renderer get exchange (IPEX) context?** §c pair 3's separator assumes the host can supply negotiation state. Whether arcviz's API should accept it, and what the render does without it, is a Phase 3/4 interface decision.
7. **Rendering the unrendered leakage of `a`-block disclosure to the *holder*.** Rule 6 shows the verifier what leaked. Whether arcviz (in holder-facing use, per [prior-art/papers-intent.md](prior-art/papers-intent.md) Q4) should *warn* pre-presentation that disclosing one field will leak sibling labels is an affordance question, not a state question — parked for Phase 4.

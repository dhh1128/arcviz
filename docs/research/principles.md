# Principles

Phase 3. Sixteen named principles, consolidated from [PLAN.md](PLAN.md)'s accumulated candidate list, the disclosure-state matrix ([disclosure-matrix.md](disclosure-matrix.md)), the substrate audits ([keripy-verification.md](keripy-verification.md), [keria-signify-surface.md](keria-signify-surface.md), [presenter-control.md](presenter-control.md)), the nine prior-art reports, and the Phase 5 reviews. Each principle is stated so it can be *violated*: it carries a short name, the statement, the evidence, and what it concretely forbids — the test a reviewer applies to a mockup. A principle no design could fail is a slogan, and none of these is meant to be one.

**Citation discipline.** This document follows [disclosure-matrix.md](disclosure-matrix.md)'s convention: spec claims cite `spec-body.md:NNN` (the audited vendored checkout `651df33e`, record `[acdc-spec-vendored-superseded]`, retained where the matrix's branch note shows the passage unchanged in substance) or `v1.1:NNN` (`toip/v1.1@910c74af`, `[acdc-spec-v11]`, the authoritative branch per AGENTS.md rule 5); paper and literature claims cite keys in `refs/sources.*.yaml` with locators; reference-implementation claims cite the sibling audit documents by section, which are themselves primary-source reads cited by `path:line`. Matrix rules are cited as "Rule N" and matrix sections as "§x", both into [disclosure-matrix.md](disclosure-matrix.md). Everything not so cited is this document's own synthesis and is marked as such. Three findings in this corpus were retracted or withdrawn after review; none is relied on here, and the closing section lists them so no reader re-imports one.

**Dependency order.** The principles are presented so that consequences follow their parents. P1 is the root. P2–P6 are its epistemic consequences once the domain's actual state space is understood. P7–P10 govern perception — how a correctly-modeled state survives contact with a human eye and an adversary. P11–P12 govern trust in content the renderer is handed. P13–P15 govern acts the renderer performs beyond depiction. P16 is the interface consequence of everything above. Where two principles pull against each other in a real case, the Tensions section at the end says so and says which wins.

---

## P1 — Disclosure honesty

**Statement.** A rendering must never let one epistemic state pass for another, or for "fine." *Absent*, *undisclosed*, *redacted*, and *unverified* — and, as the matrix decomposed them, every distinct coordinate on the six axes H/C/V/T/X/P — are different states, and any two that the evidence distinguishes must render distinguishably.

**Evidence.** This is the project's founding rule ([AGENTS.md](../../AGENTS.md); [PLAN.md](PLAN.md) §2B), the display-layer restatement of the proved-versus-guessed distinction in `oia.md` ([PLAN.md](PLAN.md):114, citing `oia.md:66`). The matrix operationalizes it: nine H-states with pairwise-distinct renders (Rule 1), the per-cell "naive lie" column (§b throughout), and the finding that every shipped wallet audited violates it — Apple and Google collapse cryptographic validity and issuer trust into one word ([prior-art/wallets.md](prior-art/wallets.md) §"What we should refuse"), and every audited codebase passes a backend chip through unexamined ([prior-art/local-codebases.md](prior-art/local-codebases.md) §4). The one shipped KERI wallet parses the DAG and discards it before drawing ([prior-art/local-codebases.md](prior-art/local-codebases.md) §2), so no prior art demonstrates compliance to copy.

**Forbids.** Any two of H1–H9 sharing a visual treatment (Rule 1's test); rendering an H2 unblinded commitment with a lock/private treatment (Rule 8 — the spec's own verdict is that such an ACDC "SHOULD be considered a public (non-confidential) ACDC," `spec-body.md:160`); a dangling referent omitted so a chain renders shorter and more complete than it is (Rule 10; the real vLEI chain has exactly this hole — [corpus-vlei-chain.md](corpus-vlei-chain.md) §3); a metadata ACDC wearing issued-credential chrome (Rule 12, with its SKP-F2 conditioning); an empty state readable as a fact about the world rather than about the payload (Rule 13). A reviewer with the matrix's fixture set in hand can catch any of these in a static mockup.

## P2 — No scalar verdicts

**Statement.** Credential state is a vector over six axes, each indexed at its own arity — H per addressable unit, C per unit not in hand, V per (check, subject), T scoping every V claim, X per artifact, P per render — and no rendering may collapse it to a scalar: not one checkmark, not one color, not one word.

**Evidence.** Depends on P1: a scalar is the mechanism by which states pass for one another. The axes and their arities are §a of the matrix; the per-(check, subject) arity was a panel correction (KRT-F2, folded in the 2026-09-11 revision — a two-edge artifact with one far node in hand and one at H7 has no honest single value for the edge-constraint check). The axis-level naive lie is documented across the whole audited field: "the vector collapsed to a scalar: one checkmark, one color, one word 'verified'" (§B3), and a checkmark not backed by a check the software performed "is a UI element, not a credential" ([hardman-proga-uielement], `prog-a.md`). Assurance being multi-axis rather than one dial is Hardman's own model ([hardman-proga-axes]; [prior-art/papers-intent.md](prior-art/papers-intent.md) §(c)).

**Forbids.** A single element whose presence summarizes more than one (check, subject) cell (Rule 2's test, as re-scoped by amendment (d)); an unlabeled whole-chain badge (Rule 11 — validity propagation is EGF-dependent, "MAY", not "MUST", `spec-body.md:1112-1116`); an issuer-bona-fides pass with no reachable aggregation-rule label (Rule 11 as amended per KRT-F4 — check 7 is itself a roll-up of check 6 at depth ≥ 2); a "trust score" or 0–100 meter of any kind.

## P3 — Unperformed is the default truth

**Statement.** For a credential merely retrieved from a store, the honest default for most verification cells is *unperformed*, and the default outcome space is {pass, unperformed, unperformable}; *fail* is an opt-in outcome a host must declare it can supply (or that arcviz earns by recomputing a check itself). Absence of a positive must never read as assurance — and absence of a negative must never read as one either.

**Evidence.** Consequence of P2 plus a substrate fact: eight of keripy's nine checks are verify-or-throw gates whose pass survives only as "the object exists"; "there is no API, stored record, or status object of the shape 'for credential X, checks 1-9 were {pass, fail, unperformed, unperformable}' anywhere in `src/keri/`" ([keripy-verification.md](keripy-verification.md) §(d)). Only revocation (`Tever.vcState`) is re-queryable. The KERIA surface makes the collapse architectural: "There is no third state visible to the client and no way, from a *successful* `GET`, to learn which of the checks above ran or how they resolved" ([keria-signify-surface.md](keria-signify-surface.md) §(c)). The fail-as-opt-in inversion is SKP-F1, folded: fail is unreachable for checks 1–4 through a store-fed host, so an offered-but-unasserted fail glyph invites the absent-flag-read-as-assurance failure. The store itself is two stores with different warrants (SEC-F3, §B6's store-identity amendment), so even "the ingestion gate did not reject this" holds only for the validated store. The COIA registry states the governing display rule this project inherits rather than invents: "An application MUST NOT render an absent flag as a positive assurance" ([prior-art/local-codebases.md](prior-art/local-codebases.md) §4, quoting `~/code/me/coia/README.md:268-270`).

**Forbids.** A bare-store fixture rendering anything other than unperformed for checks 1–7 and 9 without a host-supplied vector; any fail glyph without a host fail-declaration; a renderer claiming to distinguish fail from unperformed for edge constraints against stock keripy, which cannot make that distinction (§c pair 10 — `verifyChain` returns `None` for both a violated constraint and an absent far node); "it renders, therefore it's verified" in any guise (R0's naive lie).

## P4 — Every positive claim carries its scope

**Statement.** Every positive verification claim renders with a visible, reachable scope: the as-of horizon it holds at, the material it was computed over, and — where the check is inherently relative — the consultation set it is relative to.

**Evidence.** Consequence of P2 plus the T axis. Revocation is event reconciliation with a horizon by construction — "the verifier's task is to reconcile events, not to query a live service" ([acdc-mtc-revocation-reconciled], `acdc-and-mtc.md:54,134`), and "Freshness here is about continuity rather than immediacy" (`acdc-and-mtc.md:132`) — so the phrasing is "no revocation as of ⟨horizon⟩," never "not revoked" ([PLAN.md](PLAN.md) decisions 2026-09-05, second set, standing on the reconciliation ground after the earlier claimed paper-contradiction was retracted). Duplicity is only ever "none detected by the watchers consulted" — KERI is "duplicity-evident rather than duplicity-resistant" ([wtbo-duplicity-evident-not-resistant], `wtbo.md:113`), and structurally no consultation closes the gap (§c pair 7). Delegation passes only "as far as the KELs in hand reach" (§B3 check 5; the vLEI root KEL is absent in production data, [corpus-vlei-chain.md](corpus-vlei-chain.md) §3). A bare signature cannot even be sequenced against key compromise — the anchored/bare distinction is itself a scope claim ([signauthor2026]; `was.md:18,51-52` via [prior-art/papers-acdc.md](prior-art/papers-acdc.md) §(b)). Staleness is the LAPSED precedent, host-policied per credential ([hardman-proga-lapsed]; Rule 4).

**Forbids.** An undated pass indicator (Rule 3's test); "not revoked" or "Active" phrasing; "Delegated ✓" with no reach annotation (Rule 10); a witness count styled as endorsement ([keri-primer-witness-not-ca], `keri-primer.md:153`); anchored and bare signatures sharing a glyph (§B3 check 4's naive lie); a fixture aged past its freshness policy whose render does not change (Rule 4's test).

## P5 — Ambiguity renders as ambiguity

**Statement.** Where two states are indistinguishable from the evidence in hand, the honest rendering names the ambiguity; it never picks a side. And the mirror obligation: an anti-lie rule must not manufacture a lie — a marker asserting a definite bad state on ambiguous evidence is itself a violation of P1.

**Evidence.** The twelve indistinguishable pairs of §c are the enumeration; the section's own governing sentence is "The honest rendering names the ambiguity; it never picks a side." Erased-for-compliance and withheld-by-choice present identically ([keri-primer-erasure-vs-hash], `keri-primer.md:223`); cause-specific words are "an accusation or an excuse the artifact does not carry" (§B2). H2 vs H3 under a permissive schema is undecidable by any fetch (§c pair 11, SPC-F3). Non-possession vs declined presentation is indistinguishable *by design* of the presenting ecosystem ([arf-topic-d-embedded-disclosure-policies] REQ 4 via [prior-art/wallets.md](prior-art/wallets.md)). The mirror obligation is SKP-F2, folded into Rule 12: keripy's own builders emit `u=''` on ordinary issued credentials, so firing the metadata-decoy marker on the empty-`u` discriminator alone stamps "no issuer commitment attaches" on fully issued credentials — "a new lie manufactured by an anti-lie rule" (Rule 12's amended text).

**Forbids.** "Redacted," "withheld," "deleted," or "private by choice" on any cell whose cause input is empty (Rule 5's test); a lock treatment or a "guessable" treatment on a compact unit whose schema makes `u` optional — the four-treatment set of Rule 8 is mandatory; the full metadata marker on empty-`u` with no corroborating signal (Rule 12's test); any UI that resolves pair 1, 3, 4, 6, 7, 11, or 12 without the host input §c names as its separator.

## P6 — Artifact checks are not presenter checks

**Statement.** Every check in the V vector concerns the artifact's issuance history; none establishes that the party presenting the credential controls the AID it names as holder. That question is axis P — per render, not per check — and in a verifier-facing view the P state renders before, and at least as prominently as, the V vector. P defaults to *unknown*, which is the truth of the default transport.

**Evidence.** Consequence of P2's arity discipline, and the strongest external finding in the corpus: three independent non-Claude models converged unprompted on the absence ([reviews/2026-09-05-outside-model-refutation.md](../../reviews/2026-09-05-outside-model-refutation.md) §(b)1, adjudicated VALID). The trace confirmed it end to end: keripy's IPEX verifier never compares a grant's sender AID against the disclosed credential's holder field ([presenter-control.md](presenter-control.md) §(a)); keripy's own guardianship worked example had to build the binding by hand as application code, with a docstring saying an implementer "must port rather than copy" it ([presenter-control.md](presenter-control.md) §(a-cont)); and the default `Credentials.get()` path strips presentation context entirely ([presenter-control.md](presenter-control.md) §(c)). A stolen credential's bytes pass every artifact-side check identically (§c pair 12; R9).

**Forbids.** A verifier-facing fixture whose V vector is reachable without passing the P state (Rule 18's test); "presenter verified" backed only by store presence; any presenter-control glyph, positive or negative, in a holder-facing view — the viewing context forecloses the question, and a glyph would imply it is live (Rule 18; [presenter-control.md](presenter-control.md) §(d)).

## P7 — The last step of verification stays human

**Statement.** Automate the introduction and the evidence-gathering; never automate the human's act of deciding the evidence suffices. arcviz computes, assembles, and displays checks; it never pronounces the aggregate sufficient.

**Evidence.** `oia.md:86` via [PLAN.md](PLAN.md):128: a component that renders a green check has made the sufficiency decision on the user's behalf. The chain proves "tamper-evident provenance of the assertion graph, not that any given upstream claim is factually true" ([prior-art/papers-acdc.md](prior-art/papers-acdc.md) §Q2, on `keri-primer.md:215`); authenticity and veracity are orthogonal ([avv2025-orthogonality], `authenticity-vs-veracity.md:35`); "verified issuer" is traceability, not endorsement ([sdjwt-acdc-chaining-registries], `sdjwt-acdc.md:65`). The AAMVA two-condition trust model — signature validity and issuer bona fides as separately-verified conditions ([prior-art/wallets.md](prior-art/wallets.md) §2) — is the cleanest shipped precedent for keeping the components apart so a human can weigh them.

**Distinction this principle does not erase (ours):** rendering a computed *negative* — a failed constraint, a determinate verdict under a substituted operator (§f question 5, case 2) — is not automating the last step; it is evidence-gathering. The principle forbids the affirmative "this suffices, proceed" signal, not the display of adverse findings. Rule-out is permitted; rule-in is not — which is P8's subject.

**Forbids.** Any single affirmative "verified"/"trusted"/"valid" verdict at artifact or chain level; an auto-accept or auto-proceed flow keyed to a green state; wording that presents traceability as endorsement; collapsing "cryptographically valid" and "issuer is trustworthy" into one signal (the shipped-wallet pattern [prior-art/wallets.md](prior-art/wallets.md) explicitly tells us to refuse).

## P8 — A pill rules out; it never rules in

**Statement.** Every SAID and AID renders as an entviz pill, so an honest substitution disturbs a picture rather than hiding in a string nobody reads — but the pill's job is cheap rejection and recognition only. It must never imply that a comparison ceremony happened, and arcviz must keep a route to the real ceremony reachable.

**Evidence.** Instantiates P7 in the glance regime, bounded by measurement: against an adversary who has ground offline, "casual comparison is not marginally weak… it is broken," and a seeded comparison walk is "a requirement, not an enhancement" ([amp-diff], [amp-diff-walk-required], `amp-diff.md:324` §4.3.9). The habituated one-glance read of a pill carries only low-to-mid teens of bits ([mglance2026], `m-glance.md:16,240-245` via [prior-art/papers-identity.md](prior-art/papers-identity.md)). entviz's own `trust.ts` states the rule in four words — rule-out, never rule-in — and its reserved-but-unbuilt alias resolver already carries the same constraint ("a looked-up name is not verification," [prior-art/local-codebases.md](prior-art/local-codebases.md) §3). EVIDENCE.md's own worked example records that this project once mis-cited `amp-diff` as supporting pill-sufficiency; the paper argues the opposite ([EVIDENCE.md](EVIDENCE.md) rule 6's worked example).

**Forbids.** A pill styled with verified/current-badge connotations (§B3 check 1's naive lie — a SAID is content identity only, "A Merkle inclusion proof establishes placement in a history. A SAID establishes identity of content," [acdc-mtc-said-vs-inclusion-summary], `acdc-and-mtc.md:86`); an AGID dressed as a SAID pill (Rule 7 — it is "an aggregate, AGID, (Aggregate ID) not a SAID," `spec-body.md:661`, a different commitment object); any design in which `EntvizCompare`/`EntvizWalk`-class ceremonies are unreachable from the pill; UI copy implying two matching-looking pills were compared.

## P9 — Security-relevant state rides structure, or it is invisible

**Statement.** Two constraints bound the channel from opposite sides. Color, size, and shape cannot carry security-relevant bits against an adversary who grinds, so such state rides on discrete symbols. And no small passive indicator of any kind — including a discrete text label — reliably carries the meaning, so whatever communicates a security-relevant state must be structural: placement, layout, an interruption, the shape of the whole card.

**Evidence.** The two constraints are distinct findings from distinct literatures, and an earlier draft's claim that they were one finding was caught by the citation audit and corrected ([reviews/2026-09-05-citation-audit.md](../../reviews/2026-09-05-citation-audit.md) §(c)1; [PLAN.md](PLAN.md):130-136 carries the corrected version). Capacity: an analog quantity is recognized with tolerance and saturates near a few bits per dimension, leaving an adversary a margin to hide in; a discrete symbol certifies its bits exactly ([amp-diff-principle-5], `amp-diff.md:390`). Attention: 92% of participants entered passwords with the site-authentication image removed entirely ([schechter2007emperor]); users who do look can be fooled by well-executed counterfeits ([dhamija2006phishing]); a best-practice warning redesign moved adherence without producing comprehension ([felt2015sslwarnings]); the way out the literature offers is *interruptive, opinionated* treatment, which changes behavior without guaranteeing understanding ([akhawe2013warningland]; [prior-art/literature.md](prior-art/literature.md) cluster 2). An identifier's cryptographic-looking *form* is itself read as a security mechanism, falsely ([korir2022wallet], [prior-art/literature.md](prior-art/literature.md) cluster 1).

**Forbids.** Any security-relevant distinction carried by color alone (Rule 1's "renders distinctly" definition, §d preamble); a small corner badge or muted text label as the sole carrier of "unverified," "stale," "P unknown," or the metadata-decoy state; a palette spaced by ΔE76 rather than CIELAB lightness ([amp-diff-de76-trap]); any design claim of the form "the user will see that it is unverified" resting on a passive indicator; any claim that a warning treatment produces *comprehension* rather than adherence.

## P10 — Accessibility and adversarial robustness are one move

**Statement.** The property that makes verification state secure against a habituated attacker — hard bits riding on discrete, redundantly-encoded symbols — is the same property that makes it accessible. Print, monochrome, touch, and colour-vision deficiency are not degraded modes to patch; they are the same constraint P9 already imposed, arriving from the other side. Edge and state coding therefore ships as color plus shape plus label, or it does not ship.

**Evidence.** [amp-diff-accessibility], `amp-diff.md:372` (§5.4), which reframes the accessibility requirements as reinforcing the security posture rather than competing with it. The redundant-encoding rule is [PLAN.md](PLAN.md)'s own bullet (line 147): print may be monochrome, hover does not exist on paper or touch, colour-vision deficiency is common. MacEachren's uncertainty-visualization results add that different uncertainty categories want different sign-vehicles, so a single "greyed-out" treatment across categorically different states fails on readability grounds too ([maceachren2012semiotics], [prior-art/literature.md](prior-art/literature.md) cluster 3 — an analogy, flagged as such there).

**Forbids.** A distinction available only on hover; edge operators distinguished by stroke color alone; any state pair whose distinction survives neither greyscale print nor a screen reader; one uniform "hidden" treatment applied across H2/H3/H4/H5/H8 (which would also violate P1, but fails here even before the adversary shows up).

## P11 — Issuer content is untrusted content

**Statement.** Anything the issuer (or any third party in the artifact's supply chain) authored — attribute values, labels, rules prose, schema text, branding, any template — is untrusted input. It never executes, it never initiates network activity, and it never wears the viewer's authority: a hard, visible boundary separates the issuer-controlled canvas from the viewer-controlled frame, and no issuer content may overlap or counterfeit the frame's own state indicators. A schema is admissible input for rendering decisions only when it verifies against the committed schema SAID.

**Evidence.** The W3C render-method threat model is the deepest prior art: template code and credential values are "untrusted input from the point of view of the software running the Render process," and "Successful verification of the credential's securing mechanism confirms that the content is authentic, not that it is safe to render" ([vcrm-t2], [prior-art/w3c.md](prior-art/w3c.md)); permitted external loads are an exfiltration channel ([vcrm-t3]); the sandbox itself is a trust boundary, and even that spec steers users to its non-executing suites ([vcrm-t5]). The W3C document nowhere names chrome-spoofing as a threat — a confirmed gap in the prior art, so the frame/canvas boundary is arcviz's own containment ([prior-art/w3c.md](prior-art/w3c.md) §"What we should refuse" 3). SD-JWT VC's flat MUST-NOT-execute stance is the simpler posture this project adopts for its default path ([sdjwtvc-security]). OCA's own ecosystem retired its markup-bearing layout overlays ([prior-art/oca.md](prior-art/oca.md) §"What we should refuse"). The schema gate is SEC-F2, folded into Rule 8 and §c pair 5: the static-schema mandate is normative ("Schemas MUST be SADs and therefore verifiable against their SAIDs," `v1.1:211`; non-local URI references "MUST NOT be used," `v1.1:217`), and without the gate a substituted schema flips Rule 8's privacy treatment through Rule 8's own input. Reading attacker-controlled content as text is the safe floor ([hardman-acp-readtext] via [prior-art/papers-intent.md](prior-art/papers-intent.md) §(d)).

**Forbids.** Executing issuer-supplied code (script, template logic) in the default rendering path; issuer branding or content positioned where it can overlap, abut, or imitate arcviz's own state indicators; dereferencing a schema `$id` or any content-carried URI (also P14); classifying H2/H3 from a schema that did not SAID-verify (Rule 8's fourth-treatment test); reserved-label violations rendered as data (Rule 19 — `_` is structure, a `-` in a label is a parse error, `v1.1:55,63,65`).

## P12 — A name is not evidence

**Statement.** An alias is a private nickname, not evidence, and every human-legible name — alias, issuer display name, schema title, logo — is a claim whose provenance must be visible where it is shown. Where an alias is displayed for a remote party, the proved/guessed distinction is visible in the UI, not merely present in the data; flags are never dropped; and an unflagged alias is never treated as a verified one.

**Evidence.** [oia-alias-not-evidence] and [oia-proved-vs-guessed] ([PLAN.md](PLAN.md):127); COIA's normative rule that absence of a flag asserts nothing ([prior-art/local-codebases.md](prior-art/local-codebases.md) §4), with its `0`/`9` contrast — unverified is absence of confirming evidence, compromised is positive evidence of a problem — as the model of the distinction. Korir's participants read a DID's random-string form as itself the security mechanism ([korir2022wallet]) — a name or identifier's *appearance* generates unearned trust, which is why provenance must be carried visibly. Schema titles and issuer names arriving in the artifact are issuer content under P11; H6 shows the extreme case, where issuer/schema/edges are known only "as described by the discloser" with the issuer committed to nothing (§B1 H6; `spec-body.md:172`).

**Forbids.** An alias rendered without its flags or with a dropped flag; any treatment of an unflagged alias as verified; a schema `title` or issuer display name presented with the same visual authority as a cryptographically-derived value; a metadata ACDC's discloser-described issuer field styled identically to a committed one.

## P13 — Correlation honesty

**Statement.** Three clauses. (1) *Surface:* perfect correlators present in the rendered material render as what they are — identical SAIDs/AIDs render identically, and the residual correlators of a partially-disclosed artifact are enumerable on demand, because hiding a correlator only tells the viewer privacy exists where it does not. (2) *Never manufacture:* arcviz draws no join across presentations at all — it loads one presentation at a time and correlates only within it (Daniel Hardman's scope ruling, 2026-09-11) — and goes hunting for nothing the viewer was not given. (3) *No corpus-level negatives:* committed absence within an H1 block is the one warranted negative and renders as that issuance-time fact; every corpus-level absence renders scoped to the material in hand, never as exhaustive.

**Evidence.** The correlation-honesty decision ([PLAN.md](PLAN.md) decisions 2026-09-05, correcting an earlier draft rule that would have suppressed facts). An AID match is an equality test, not an inference — the vLEI leaf's `a.i` is "pseudonymous but linkable across every system that sees this credential" ([corpus-vlei-chain.md](corpus-vlei-chain.md) §7) — and partial identifiers stack toward full identification ([eff-info-theory]: ~33 bits identifies a person; birthday + ZIP + gender ≈ 33.32). The entviz pill is a correlator-surfacing device by design; a suppression rule would fight the component arcviz builds on ([PLAN.md](PLAN.md):146). Clause 2 is [hardman-if-owner] ("never a default, never an inference a stranger is meant to draw, never a leak the software condones behind her back") applied at the join boundary, and negative facts are the whistleblower-identification mechanism ([hardman-wbca-negative]). Clause 3's carve-out is the Rule 13 rewrite after two outside seats caught the original "no negative claims, anywhere" contradicting the matrix's own committed-absence cell (refutation §(b)2, adjudicated VALID). Rendering selective disclosure as achieved privacy while SAIDs, issuer AID, and registry id correlate perfectly is the residual lie (§B5); a bulk instance rendered "anonymous" flattens a scoped, topology-dependent protection ([corpus-keripy-examples.md](corpus-keripy-examples.md) §(b)4).

**Forbids.** A silently-drawn cross-presentation edge, or an inferred edge sharing a disclosed edge's stroke (Rule 14's tests — disclosed-here, disclosed-elsewhere, and inferred-by-equality are three edge classes that must not share a treatment); "unlinkable"/"anonymous" as absolutes; a partial-disclosure view with no route to its residual-correlator enumeration; "no linked credentials found" or any empty state readable as a fact about the world (Rule 13's test); and any edge drawn between two presentations, explicit or otherwise — arcviz loads one presentation at a time and correlates only within it (Daniel Hardman's scope ruling, 2026-09-11; [affordances.md](affordances.md) AF14, retired).

## P14 — Rendering is passive: expansion is local, acquisition is a protocol act

**Statement.** arcviz performs no network act as a side effect of rendering. Expanding material already in hand is free and leaks nothing; an unresolved unit renders as H7/unperformable rather than triggering a fetch. Acquiring material not in hand is a protocol act — an IPEX exchange, an explicit OOBI resolution — that belongs to the host, sits on an intent boundary, and is never triggered by hover or click-to-expand. The principle is host-conditional in one direction only: for hosts that do resolve references over the network, the affordance inventory must ask which regime it is in rather than assume.

**Evidence.** The KERIA/signify substrate makes the safe half structural: KERIA refuses to save a credential whose chain does not resolve, so every far node of a held credential is already local and embedded in the response — "expanding an edge that's already in the payload's `chains` array is a local, in-memory operation" — and there is no fetch-by-bare-SAID anywhere in the surface ([keria-signify-surface.md](keria-signify-surface.md) §(e)). This corrected an earlier draft's "every expansion is a potential disclosure" ([PLAN.md](PLAN.md):139-141), and [intent-boundaries-dont-imagine] (`intent-boundaries.md:84`) forbids re-inventing the boundary where it does not exist. The dangerous half is PRV-F3, folded as Rule 17: a render-time fetch is a per-view disclosure, and against an issuer-side surface it re-creates the point-of-validation leak the spec's Registrar/Observer split exists to delete — "no forced phone home validation" (`v1.1:1707`). No verification-time phone-home is a standing position of the papers corpus ([hardman-proga-phonehome]; `sda.md:119` via [prior-art/papers-intent.md](prior-art/papers-intent.md) §(c)), as is the rule against outbound requests initiated by content ([hardman-acp-dontcallme]).

**Forbids.** Any arcviz-initiated network request while rendering a fixture with a dangling referent (Rule 17's test is a network monitor); hover-to-fetch or expand-to-fetch affordances; schema resolution, OCA-overlay retrieval, or remote-image loading driven by credential content (also P11); a host-fetch freshness claim rendered without naming the surface class it was acquired from (verifier-side Observer vs issuer-side witness/Registrar — §B4's caveat, §c pair 6).

## P15 — Static output degrades honestly

**Statement.** A printed, screenshotted, or exported credential carries no live verification. Every V indicator — and any P claim — in static output renders as a historical record ("checked ⟨scope⟩ by ⟨tool⟩"), never as live state; and the terms of use travel with the render, so encumbered data never exports as unencumbered.

**Evidence.** No audited ecosystem designed for the moment a credential leaves the live channel — the four wallet paradigms' shared silence is "a confirmed gap, not an oversight in this research pass" ([prior-art/wallets.md](prior-art/wallets.md) §5) — so Rule 15 is arcviz's own contribution, flagged as new per [PLAN.md](PLAN.md)'s affordance-scope decision. The mDL ecosystem's "flash pass" prohibition names the failure mode from the verifier side ([presenter-control.md](presenter-control.md) §(e), quoting the AAMVA guide's Note 1). Terms-propagation is PRV-F2, folded as Rule 16: Chain-Link Confidentiality's propagation is normative — terms "MUST be applied by each subsequent Discloser to each subsequent Disclosee" (`v1.1:1804`) — and a render showing encumbered data as unencumbered is where the chain silently breaks. The former obligation that an export "carries what a re-verifier needs" was split off as unbounded and parked (SKP-F5; §f question 10) — this principle deliberately does not include it, and reintroducing it requires the demand test that question names.

**Forbids.** Identical verification chrome in live and print media output (Rule 15's diff test); a static export carrying a live-styled presenter-control badge; an export of attribute values from a credential with a non-empty `r` section that carries no terms reference (Rule 16's test); any static render whose overall authority is indistinguishable from the live view's.

## P16 — The host supplies what the artifact cannot; absence degrades precision, never honesty

**Statement.** Everything arcviz needs beyond the artifact — cause attestations, exchange context, fetch logs, verified schemas, event streams and per-credential freshness policies, outcome-space declarations, store identity, presentation-provenance evidence, retention bounds — is a host input with defined absent-semantics, and arcviz is fully conformant and honest with every channel empty. Host-supplied claims render with their own provenance and scope; arcviz never invents a value for a missing input and never silently defaults one.

**Evidence.** The consequence of P3–P6 and P13–P15 taken together, stated as SKP-F3's folded baseline (§c's baseline paragraph): each channel's honest default for absence is already specified — cause unknown (Rule 5), no-freshness-policy visible (Rule 4), protection-unknown (Rule 8), scoped duplicity (pair 7), P unknown (Rule 18) — so the channels are one optional annotation vocabulary, not seven contracts. The freshness policy is host-supplied per credential by Daniel's ruling, with "no freshness policy supplied" its own visible state ([PLAN.md](PLAN.md) decisions 2026-09-05, second set). Store identity defaults to the weaker reading when undeclared (§B6's store-identity amendment). An unattested cause string "is a claim, not a fact, and should render as such" (§c pair 1). The retracted "governing operator profile" input is *not* in this list and must not return: one declared spec version defines one operator table, and arcviz implements it as `v1.1` states it ([PLAN.md](PLAN.md) decisions, retraction of 2026-09-10; [reviews/2026-09-06-operator-semantics-adjudication.md](../../reviews/2026-09-06-operator-semantics-adjudication.md) Correction).

**Forbids.** A staleness verdict rendered for a credential with no supplied policy, or one global window applied across credentials (Rule 4's tests); a silent default anywhere a visible absent-state is specified; host-supplied attestations (cause, P evidence) rendered without their own provenance (Rules 5 and 18); any design reintroducing a per-credential operator-profile input.

## Tensions, and which side wins

These are the places where two principles pull against each other in a real case. Each is stated with its resolution, because an unacknowledged tension is a bug a designer will hit.

**T1. Surfacing correlators (P13.1) vs. never linking facets (P13.2).** Within one rendered body of material, identical values render identically — the fact is already in the viewer's hands, and suppressing it asserts privacy that does not exist. Across presentations there is no tension left to adjudicate: Daniel Hardman's scope ruling of 2026-09-11 loads one presentation at a time, so the join is not an act arcviz can perform and [hardman-if-owner] is satisfied by construction rather than by discipline. The boundary is *what the viewer was given as one presentation*; surfacing wins inside it, and outside it there is nothing to draw. Recorded as a resolved tension rather than deleted, because the reasoning is what justifies surfacing aggressively *within* the boundary.

**T2. Structural prominence (P9) vs. finite attention.** P9 demands structural treatment for security-relevant state, but the matrix names dozens of distinct states, and a design that makes everything structurally loud makes nothing so. **Resolution (ours, for Phase 4 and 6 to hold):** P1 governs *distinctness* — every state pair distinguishable on inspection, by discrete symbol per P9's capacity constraint. P9's *structural* budget is reserved for the states whose naive lie is specifically "reads as fine": the stale state (§B4 — "the one most likely to be silently rendered as fine"), P = unknown in a verifier-facing view (Rule 18 — the fully-green artifact vector with the presenter question unasked), the metadata-decoy state (Rule 12, when its conditioned trigger fires), and the H2-guessable state (Rule 8's gravest lie). A design that spends structure on, say, the syntactic presence of an edge operator has inverted the budget — pair 2 requires *suppressing* that difference.

**T3. Disclosure honesty (P1) vs. manufacturing certainty (P5).** P1 pushes toward marking every deviation loudly; P5 shows the failure mode: Rule 12's original trigger would have stamped a definite bad state on ambiguous evidence. Where evidence is ambiguous, P5 wins — the render names the ambiguity, and the "possibly" form is the honest maximum. P1 is not weakened by this: the named-ambiguity state is itself a distinct state that must not pass for either resolved state or for fine.

**T4. The last step stays human (P7) vs. rendering determinate negatives.** Default injection means a token outside the `v1.1` operator table yields a determinate verdict that can be *fail* (§f question 5, case 2), and a host may declare fail-capable checks (P3). Rendering these is not automating the last step: P7 forbids the affirmative sufficiency signal, not adverse evidence. The asymmetry is deliberate and is the same one P8 states for pills: rule-out is cheap and honest, rule-in is the human's act.

**T5. Passive rendering (P14) vs. the T axis wanting fresher horizons (P4).** An old horizon makes staleness likely; fetching would freshen it but leaks. P14 wins at render time, unconditionally: arcviz renders the horizon it has and marks staleness per Rule 4. Freshening is the host's act, on the host's schedule, through a surface whose class the freshness input names. A design that "helpfully" refreshes on open has chosen the OCSP leak the substrate was built to avoid (`v1.1:1707`).

**T6. Schema-driven rendering (P1, Rule 6/8 need the schema) vs. issuer content untrusted (P11).** The schema is simultaneously required input and attack surface. Resolution: the SAID-verification gate (SEC-F2). A verified schema is admissible; an unverified one degrades the render to "protection unknown" — honesty preserved at the cost of precision, per P16. And even a verified schema's `anyOf` candidates must not be enumerated onto hidden aggregate elements (Rule 6, R2's naive lie) — the schema informs *shape*, never manufactures *content*.
